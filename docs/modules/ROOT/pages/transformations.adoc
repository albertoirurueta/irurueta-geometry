= Transformations
:description: The Euclidean, metric, affine and projective transformation hierarchy in irurueta-geometry: degrees of freedom, invariants, the plane at infinity, absolute conic, and how each entity transforms.
:keywords: Euclidean transformation, affine transformation, projective transformation, metric transformation, plane at infinity, absolute conic, transformation hierarchy

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

A **transformation** maps geometric entities (points, lines, planes, conics, quadrics, cameras) onto other
entities of the same kind. `irurueta-geometry` organizes transformations into a **stratified hierarchy** of
increasing generality -- Euclidean, metric, affine and projective -- each one a special case of the next. This
page explains that hierarchy, what each family preserves, and how the library actually implements it in
`com.irurueta.geometry.Transformation2D` / `Transformation3D` and their subclasses.

== The hierarchy

image::transformation-hierarchy.svg[Transformation hierarchy: Euclidean, Metric, Affine and Projective, applied to a reference square]

[cols="1,2,1,3",options="header"]
|===
|Family |Adds on top of the previous family |DOF (2D / 3D) |Preserves / fixes at infinity

|Euclidean (rigid)
|rotation + translation
|3 / 6
|distances, angles, areas/volumes; trivially fixes stem:[\boldsymbol{\Pi}_\infty], stem:[\boldsymbol{\Omega}_\infty] and stem:[\mathbf{Q}^*_\infty] *and* the absolute scale.

|Metric (similarity)
|+ uniform scale
|4 / 7
|angles, ratios of distances, shape; fixes the plane at infinity stem:[\boldsymbol{\Pi}_\infty] *and* the absolute conic stem:[\boldsymbol{\Omega}_\infty] / dual absolute quadric stem:[\mathbf{Q}^*_\infty] (up to scale) -- but not the absolute scale itself.

|Affine
|+ independent axis scaling and skew (general linear map)
|6 / 12
|parallelism, ratios of lengths on parallel lines, ratios of areas/volumes; fixes the plane at infinity stem:[\boldsymbol{\Pi}_\infty] *as a set* (not pointwise), but not stem:[\boldsymbol{\Omega}_\infty]/stem:[\mathbf{Q}^*_\infty].

|Projective
|+ a general homography, defined up to scale
|8 / 15
|incidence (collinearity/coplanarity), cross-ratio of 4 collinear points; fixes none of stem:[\boldsymbol{\Pi}_\infty], stem:[\boldsymbol{\Omega}_\infty] or stem:[\mathbf{Q}^*_\infty] in general.
|===

The DOF and invariants above match the standard 2D hierarchy in
xref:reference.adoc#bib-hartley-zisserman[Hartley & Zisserman] table 2.4 (p.44) and the 3D hierarchy in their
table 3.2 (p.78), and are worked out from first principles in
xref:reference.adoc#bib-phd-report[Irurueta's PhD thesis]
xref:attachment$irurueta-phd-thesis.pdf#page=54[table 1.4 (p.42)]. The rest of this page is devoted to
*why* those particular quantities -- the plane at infinity, the absolute conic and the dual absolute quadric --
are exactly the ones that separate affine from metric from Euclidean.

Each family is strictly more general than the previous one: every Euclidean transformation is also a metric
transformation (with scale = 1), every metric transformation is also affine, and every affine transformation is
also projective. `irurueta-geometry` exposes this with one-directional "upgrade" converters rather than a shared
supertype:

[mermaid]
....
classDiagram
    class Transformation2D
    class Transformation3D
    class EuclideanTransformation2D
    class MetricTransformation2D
    class AffineTransformation2D
    class ProjectiveTransformation2D
    Transformation2D <|-- EuclideanTransformation2D
    Transformation2D <|-- AffineTransformation2D
    Transformation2D <|-- ProjectiveTransformation2D
    EuclideanTransformation2D <|-- MetricTransformation2D
    EuclideanTransformation2D ..> MetricTransformation2D : toMetric()
    MetricTransformation2D ..> AffineTransformation2D : toAffine()
    AffineTransformation2D ..> ProjectiveTransformation2D : toProjective()
....

The 3D classes (`Transformation3D`, `EuclideanTransformation3D`, `MetricTransformation3D`,
`AffineTransformation3D`, `ProjectiveTransformation3D`) mirror this exactly. Two details worth noting:

* `MetricTransformation2D`/`3D` **extends** `EuclideanTransformation2D`/`3D`, adding a single `scale` field --
  metric/similarity really is "Euclidean plus scale" in the implementation, not an independent class.
* `AffineTransformation2D`/`3D` and `ProjectiveTransformation2D`/`3D` extend `Transformation2D`/`3D` directly
  (they do *not* extend `Metric*`/`Euclidean*`). They only expose one-way upgrade methods (`toAffine()`,
  `toProjective()`); there is no built-in "downgrade" that tries to recover a simpler transformation from a more
  general one.

`ProjectiveTransformation2D`/`3D` makes the nesting explicit in its own javadoc: its internal matrix has an
extra "projective parameters" row that is `[0, ..., 0, 1]` (up to scale) for every transformation that is really
just affine, metric, or Euclidean in disguise.

== Internal representation

[cols="1,3",options="header"]
|===
|Class |Representation

|`EuclideanTransformation2D`/`3D`
|a `Rotation2D`/`Rotation3D` plus a translation vector; point maps to stem:[\mathbf{p}' = \mathbf{R}\,\mathbf{p} + \mathbf{t}].

|`MetricTransformation2D`/`3D`
|the same rotation/translation, plus a scalar `scale`; point maps to stem:[\mathbf{p}' = s\,(\mathbf{R}\,\mathbf{p}) + \mathbf{t}].

|`AffineTransformation2D`/`3D`
|a general (non-orthonormal) linear map matrix `A` (2&#215;2 / 3&#215;3) plus a translation; point maps to
stem:[\mathbf{p}' = \mathbf{A}\,\mathbf{p} + \mathbf{t}]. Rotation and independent-scale/skew components are recovered on demand from `A` via
RQ decomposition (`getRotation()`, `getParameters()` / `AffineParameters2D`/`3D`).

|`ProjectiveTransformation2D`/`3D`
|a single homogeneous matrix `T` (3&#215;3 / 4&#215;4), defined up to scale; a homogeneous point maps to
stem:[\mathbf{p}' = \mathbf{T}\,\mathbf{p}] directly, with no separate translation step.
|===

== How other geometric entities transform

Because points, lines/planes and conics/quadrics play different roles in projective duality, they don't all
transform the same way. Given a transformation matrix `T` (2D: 3&#215;3, 3D: 4&#215;4) and its application to a
point `p' = T&#183;p`, the library implements:

[cols="1,2",options="header"]
|===
|Entity |Transform rule

|Point2D / Point3D
|stem:[\mathbf{p}' = \mathbf{T}\,\mathbf{p}] (direct forward map)

|Line2D / Plane
|stem:[\mathbf{l}' = \mathbf{T}^{-\mathsf T}\,\mathbf{l}] (inverse-transpose -- lines/planes are covectors)

|Conic / Quadric
|stem:[\mathbf{C}' = \mathbf{T}^{-\mathsf T}\,\mathbf{C}\,\mathbf{T}^{-1}] (inverse-transpose on both sides)

|DualConic / DualQuadric
|stem:[\mathbf{C}'^{-1} = \mathbf{T}\,\mathbf{C}^{-1}\,\mathbf{T}^{\mathsf T}] (forward on both sides -- duals transform contragradiently to their primal)

|PinholeCamera
|camera matrix stem:[\mathbf{P}' = \mathbf{P}\,\mathbf{T}^{-1}]

|Polygon / Triangle
|vertices transformed individually (each vertex is just a point)

|Line3D
|derived by transforming the two planes that define it
|===

The inverse-transpose rule for lines/planes/conics/quadrics is the standard projective-duality argument, and it
appears as an inline comment repeated across every subclass's `transform(Conic, ...)` /
`transform(Line2D, ...)` method, e.g.:

[source]
----
// point' * conic * point = 0
// point' * T' * transformedConic * T * point = 0
// where: transformedPoint = T * point
// Hence: transformedConic = T^-1' * conic * T^-1
----

All of these transform methods normalize the input, invert `T` once, and re-normalize before multiplying --
this is a numerical-stability pattern repeated identically across the Euclidean/Metric/Affine/Projective
implementations of every entity above.

== Invariants: what fixes what

The table above says that affine transformations preserve parallelism while metric transformations preserve
angles. Both facts have a single, precise algebraic root: **each stratum is exactly the subgroup of the
projective linear group that fixes one particular geometric object living at infinity**. Affine transformations
are exactly the ones that fix the plane at infinity stem:[\boldsymbol{\Pi}_\infty] as a set; metric (similarity)
transformations are exactly the ones that, in addition, fix the absolute conic stem:[\boldsymbol{\Omega}_\infty] (or,
equivalently, the dual absolute quadric stem:[\mathbf{Q}^*_\infty]); Euclidean transformations are metric
transformations with the remaining scale freedom pinned to 1. This section works through why, following
xref:reference.adoc#bib-phd-report[Irurueta's PhD thesis]
xref:attachment$irurueta-phd-thesis.pdf#page=33[&#167;1.4] and
xref:reference.adoc#bib-hartley-zisserman[Hartley & Zisserman] &#167;3.5-3.7.

=== The plane at infinity fixes the affine stratum

In any projective frame of stem:[\mathbb{P}^3], the points with homogeneous last coordinate
stem:[W = 0] form a plane, the **plane at infinity** stem:[\boldsymbol{\Pi}_\infty]. In a frame that is already
affine (or metric, or Euclidean) it takes the canonical form

[stem]
++++
\boldsymbol{\Pi}_\infty = (0, 0, 0, 1)^{\mathsf T}
++++

(xref:attachment$irurueta-phd-thesis.pdf#page=35[PHD eq. 1.118]; HZ eq. 3.1-analogue for 3-space). This is
exactly the constant returned by
`Plane.createCanonicalPlaneAtInfinity()`. Under an arbitrary projective transformation, however,
stem:[\boldsymbol{\Pi}_\infty] moves like any other plane -- the library's own rule stem:[\mathbf{l}' = \mathbf{T}^{-\mathsf T} \mathbf{l}]
applies to it too, and in an arbitrary projective frame it can be *anywhere*: 3 vanishing points fix 3 independent
directions, and the plane they span identifies where stem:[\boldsymbol{\Pi}_\infty] actually sits in that frame
(xref:attachment$irurueta-phd-thesis.pdf#page=34[PHD fig. 1.9]). This is exactly what `plane-at-infinity.svg` below illustrates: on the left, a cube seen through an
uncalibrated homography, where 3 vanishing points stem:[\mathbf{M}_X, \mathbf{M}_Y, \mathbf{M}_Z] mark 3 points of stem:[\boldsymbol{\Pi}_\infty];
on the right, the same cube after upgrading to the affine stratum, where those vanishing points have moved back
out to infinity and the cube's edges are visibly parallel again.

image::plane-at-infinity.svg[The plane at infinity identified by 3 vanishing points in a projective frame, and sent back to infinity by an affine upgrade]

**Claim (xref:attachment$irurueta-phd-thesis.pdf#page=36[PHD eq. 1.121-1.123]; HZ Result 3.7): a projective
transformation fixes stem:[\boldsymbol{\Pi}_\infty] as a set
if, and only if, it is an affinity.** Write a general affine transformation in the library's own block form
(the exact shape produced by `AffineTransformation3D.toProjective()`, see below):

[stem]
++++
\mathbf{T}_A = \begin{bmatrix} \mathbf{A} & \mathbf{t} \\ \mathbf{0}^{\mathsf T} & 1 \end{bmatrix}, \qquad \det(\mathbf{A}) \neq 0
++++

Applying the plane-transform rule directly to the canonical stem:[\boldsymbol{\Pi}_\infty]
(xref:attachment$irurueta-phd-thesis.pdf#page=36[PHD eq. 1.121]):

[stem]
++++
\mathbf{T}_A^{\mathsf T} \cdot \boldsymbol{\Pi}_\infty =
\begin{bmatrix} \mathbf{A}^{\mathsf T} & \mathbf{0} \\ \mathbf{t}^{\mathsf T} & 1 \end{bmatrix}
\begin{bmatrix} 0 \\ 0 \\ 0 \\ 1 \end{bmatrix}
= \begin{bmatrix} 0 \\ 0 \\ 0 \\ 1 \end{bmatrix} = \boldsymbol{\Pi}_\infty
++++

so stem:[\boldsymbol{\Pi}_\infty] is a fixed point of stem:[\mathbf{T}_A^{\mathsf T}], and hence (taking inverse-transposes,
xref:attachment$irurueta-phd-thesis.pdf#page=36[PHD eq. 1.123]) also of the library's covector rule stem:[\boldsymbol{\Pi}_\infty' = \mathbf{T}_A^{-\mathsf T}\boldsymbol{\Pi}_\infty = \boldsymbol{\Pi}_\infty].
Notice this is *set*-invariance, not pointwise invariance: individual points within stem:[\boldsymbol{\Pi}_\infty] --
i.e. individual directions/vanishing points -- are free to move around, as long as they stay on the plane. The
converse (any projective `H` that fixes stem:[\boldsymbol{\Pi}_\infty] as a set must have a last row proportional to
stem:[(0,0,0,1)], i.e. must be affine) is HZ Result 3.7, proved the same way the 2D analogue (Result 2.17)
is: fixing a hyperplane algebraically forces the homography's action on the complementary coordinate to vanish.

This is also precisely how you *find* the affine upgrade once stem:[\boldsymbol{\Pi}_\infty] has been identified in an
arbitrary projective frame: any matrix of the form

[stem]
++++
\mathbf{T}_{PA} = \begin{bmatrix} \mathbf{I}_{3\times3} & \mathbf{0}_3 \\ \boldsymbol{\pi}_\infty^{\mathsf T} & 1 \end{bmatrix}
++++

(xref:attachment$irurueta-phd-thesis.pdf#page=37[PHD eq. 1.125], with stem:[\boldsymbol{\pi}_\infty] the first 3
coordinates of the identified stem:[\boldsymbol{\Pi}_\infty],
scaled so its last coordinate is 1 -- xref:attachment$irurueta-phd-thesis.pdf#page=37[PHD eq. 1.126]) sends that
plane back to its canonical position, because its
last row *is* stem:[\boldsymbol{\Pi}_\infty^{\mathsf T}]. Any stem:[\mathbf{T}_{PA}' = \begin{bmatrix} \mathbf{A} & \mathbf{0} \\ \boldsymbol{\pi}_\infty^{\mathsf T} & 1\end{bmatrix}] with non-singular stem:[\mathbf{A}] works equally well
(xref:attachment$irurueta-phd-thesis.pdf#page=37[PHD eq. 1.127]) --
stem:[\mathbf{T}_{PA}] is simply the simplest choice.

=== The absolute conic and dual absolute quadric fix the metric stratum

Fixing stem:[\boldsymbol{\Pi}_\infty] buys parallelism but says nothing about angles: an affine map can still skew a
square into an arbitrary parallelogram. To pin down angles, both HZ and PHD start from the elementary fact that
two vectors are orthogonal iff their dot product vanishes, stem:[\mathbf{v}_1^{\mathsf T} \mathbf{v_2} = 0]
(xref:attachment$irurueta-phd-thesis.pdf#page=41[PHD eq.
1.143-1.144]). Pushing that relation through an arbitrary homography stem:[\mathbf{m}_i' = \mathbf{H} \mathbf{m}_i] gives
(xref:attachment$irurueta-phd-thesis.pdf#page=42[PHD eq. 1.145-1.148]):

[stem]
++++
\mathbf{m}_1^{\mathsf T} \mathbf{m}_2 = (\mathbf{H}^{-1}\mathbf{m}_1')^{\mathsf T}(\mathbf{H}^{-1}\mathbf{m}_2') = {\mathbf{m}_1'}^{\mathsf T}\,\underbrace{\mathbf{H}^{-\mathsf T}\mathbf{H}^{-1}}_{=\,\mathbf{C}'}\,\mathbf{m}_2' = 0
++++

and stem:[\mathbf{C}' = \mathbf{H}^{-\mathsf T}\mathbf{H}^{-1}] is symmetric, i.e. exactly the shape of a conic transformed by the
library's own rule stem:[\mathbf{C}' = \mathbf{T}^{-\mathsf T}\mathbf{C}\mathbf{T}^{-1}] with stem:[\mathbf{C} = \mathbf{I}_{3\times3}] in the *metric*
frame. Running the same argument in 3D with planes and their director vectors
(xref:attachment$irurueta-phd-thesis.pdf#page=43[PHD eq. 1.154-1.158]) shows that
the analogous *quadric* that certifies orthogonality of planes in a metric frame is degenerate --
stem:[\mathbf{Q}_M^* = \mathrm{diag}(1,1,1,0)] -- because the extra row/column that would encode a translation-like
term must vanish for perpendicularity to be translation-independent.

These two constants are, respectively, the **absolute conic** stem:[\boldsymbol{\Omega}_\infty] and the **dual absolute
quadric** stem:[\mathbf{Q}^*_\infty]: the point conic that lies *on* stem:[\boldsymbol{\Pi}_\infty] (formed by
stem:[\boldsymbol{\Pi}_\infty] intersecting the absolute quadric stem:[\mathbf{Q}_\infty]), and the degenerate quadric whose
tangent planes are exactly the planes tangent to stem:[\boldsymbol{\Omega}_\infty]
(xref:attachment$irurueta-phd-thesis.pdf#page=40[PHD &#167;1.4.3.1, fig. 1.12]). In a
metric frame:

[stem]
++++
\boldsymbol{\Omega}_\infty = \boldsymbol{\Omega}_\infty^{*} = \mathbf{I}_{3\times3}, \qquad
\mathbf{Q}^*_\infty = \begin{bmatrix} \mathbf{I}_{3\times3} & \mathbf{0}_3 \\ \mathbf{0}_3^{\mathsf T} & 0 \end{bmatrix} = \mathrm{diag}(1,1,1,0)
++++

(xref:attachment$irurueta-phd-thesis.pdf#page=45[PHD eq. 1.160/1.162/1.169]; HZ eq. 3.21/3.24 -- identical
constants). Algebraically stem:[\boldsymbol{\Omega}_\infty]
is a conic of *purely imaginary* points, stem:[x^2+y^2+1=0] i.e. a "circle" of imaginary radius
stem:[i=\sqrt{-1}] (PHD xref:attachment$irurueta-phd-thesis.pdf#page=45[eq. 1.163],
xref:attachment$irurueta-phd-thesis.pdf#page=44[fig. 1.14]); stem:[\mathbf{Q}_\infty] is the limit of an
ever-more-squashed
sphere stem:[\mathrm{diag}(1,1,1,k)] as stem:[k\to\infty]
(xref:attachment$irurueta-phd-thesis.pdf#page=46[PHD eq. 1.168, fig. 1.15]; HZ calls this a
"rim quadric" -- picture an ellipsoid squashed to a pancake, with stem:[\boldsymbol{\Omega}_\infty] as its rim). These
are exactly the shapes `absolute-conic-quadric.svg` below depicts.

image::absolute-conic-quadric.svg[The absolute conic Omega-infinity on the plane at infinity, and the dual absolute quadric Q-star-infinity meeting the plane at infinity in Omega-infinity]

**Claim (PHD xref:attachment$irurueta-phd-thesis.pdf#page=48[Proof 1.6],
xref:attachment$irurueta-phd-thesis.pdf#page=47[eq. 1.170-1.178]; HZ Result 3.9/3.10): a projective transformation
fixes
stem:[\boldsymbol{\Omega}_\infty] (equivalently stem:[\mathbf{Q}^*_\infty], up to the overall scale any projective quantity
is defined up to) if, and only if, it is a similarity.** Sufficiency is a direct computation: writing a
similarity in the library's block form (matching `EuclideanTransformation3D.toMetric()`'s output shape) and
applying the *dual*-quadric transform rule stem:[\mathbf{Q}^{*\prime} = \mathbf{T}\,\mathbf{Q}^*\,\mathbf{T}^{\mathsf T}] (the library's own
forward-forward rule for duals) gives

[stem]
++++
\mathbf{T} = \begin{bmatrix} \sigma \mathbf{R} & \mathbf{t} \\ \mathbf{0}_3^{\mathsf T} & 1 \end{bmatrix}
\;\Longrightarrow\;
\mathbf{Q}^{*\prime}_\infty = \mathbf{T}\,\mathbf{Q}^*_\infty\,\mathbf{T}^{\mathsf T}
= \sigma^2 \begin{bmatrix} \mathbf{R} \mathbf{R}^{\mathsf T} & \mathbf{0}_3 \\ \mathbf{0}_3^{\mathsf T} & 0 \end{bmatrix}
= \sigma^2 \begin{bmatrix} \mathbf{I}_{3\times3} & \mathbf{0}_3 \\ \mathbf{0}_3^{\mathsf T} & 0 \end{bmatrix} = \sigma^2\,\mathbf{Q}^*_\infty
++++

using stem:[\mathbf{R}\mathbf{R}^{\mathsf T}=I_{3\times3}] for any rotation
(xref:attachment$irurueta-phd-thesis.pdf#page=47[PHD eq. 1.170-1.173]) -- i.e.
stem:[\mathbf{Q}^*_\infty] is reproduced up to the scalar stem:[\sigma^2], which is exactly the "up to scale"
sense in which any projective entity is defined. For necessity, take an *arbitrary* projective
stem:[\mathbf{T} = \begin{bmatrix} \mathbf{A} & \mathbf{b} \\ \mathbf{c}^{\mathsf T} & d \end{bmatrix}] and demand
stem:[\mathbf{T}\,\mathbf{Q}^*_\infty\,\mathbf{T}^{\mathsf T} \propto \mathbf{Q}^*_\infty]:

[stem]
++++
\mathbf{T}\,\mathbf{Q}^*_\infty\,\mathbf{T}^{\mathsf T} =
\begin{bmatrix} \mathbf{A} & \mathbf{b} \\ \mathbf{c}^{\mathsf T} & d \end{bmatrix}
\begin{bmatrix} \mathbf{I}_{3\times3} & \mathbf{0}_3 \\ \mathbf{0}_3^{\mathsf T} & 0 \end{bmatrix}
\begin{bmatrix} \mathbf{A}^{\mathsf T} & \mathbf{c} \\ \mathbf{b}^{\mathsf T} & d \end{bmatrix}
= \begin{bmatrix} \mathbf{A} \mathbf{A}^{\mathsf T} & \mathbf{A} \mathbf{c} \\ \mathbf{c}^{\mathsf T} \mathbf{A}^{\mathsf T} & \mathbf{c}^{\mathsf T} \mathbf{c} \end{bmatrix}
++++

Matching this against latexmath:[\mathrm{diag}(1,1,1,0)] (up to the scalar latexmath:[\sigma^2] discussed above)
forces

[stem]
++++
\mathbf{A} \mathbf{A}^{\mathsf T} = \sigma^2 \mathbf{I}_{3\times3}, \qquad \mathbf{A} \mathbf{c} = \mathbf{0}_3, \qquad c^{\mathsf T} c = 0 \;\Longrightarrow\; c = \mathbf{0}_3
++++

(xref:attachment$irurueta-phd-thesis.pdf#page=49[PHD eq. 1.177]). So stem:[\mathbf{c}] -- the projective row that
would otherwise move stem:[\boldsymbol{\Pi}_\infty] -- must
vanish, and stem:[\mathbf{A} = \sigma \mathbf{R}] must be a *scaled rotation* (the condition stem:[\mathbf{A}\mathbf{A}^{\mathsf T}=\sigma^2 \mathbf{I}]
is exactly "orthogonal up to a positive scalar"). That leaves precisely

[stem]
++++
\mathbf{T} = \begin{bmatrix} \sigma \mathbf{R} & \mathbf{b} \\ \mathbf{0}_3^{\mathsf T} & 1 \end{bmatrix}
++++

a similarity transformation (xref:attachment$irurueta-phd-thesis.pdf#page=49[PHD eq. 1.178]) -- and since
stem:[\boldsymbol{\Omega}^*_\infty] sits in the top-left
stem:[3\times3] minor of stem:[\mathbf{Q}^*_\infty] (xref:attachment$irurueta-phd-thesis.pdf#page=46[PHD eq.
1.166]), a transformation that fixes
stem:[\mathbf{Q}^*_\infty] fixes stem:[\boldsymbol{\Omega}^*_\infty] (and hence stem:[\boldsymbol{\Omega}_\infty = (\Omega^*_\infty)^{-1}]) too. HZ Result 3.10 gives the equivalent block-matrix proof for
stem:[\mathbf{Q}^*_\infty=\mathrm{diag}(1,1,1,0)] directly, and Result 3.9 proves the corresponding statement for
stem:[\boldsymbol{\Omega}_\infty] itself by first invoking Result 3.7 (any transformation fixing a conic *on*
stem:[\boldsymbol{\Pi}_\infty] must first fix stem:[\boldsymbol{\Pi}_\infty], hence be affine) and then showing the affine part
must be orthogonal up to scale.

=== Upgrading between strata

Because affine upgrade only needs stem:[\boldsymbol{\Pi}_\infty] while metric upgrade needs stem:[\boldsymbol{\Omega}_\infty]/
stem:[\mathbf{Q}^*_\infty] as well, the two upgrades compose. Combining stem:[\mathbf{T}_{PA}] (eq. 1.125) with the
affine&#8594;metric matrix stem:[\mathbf{T}_{AM} = \begin{bmatrix} \mathbf{A}^{-1} & \mathbf{0}_3 \\ \mathbf{0}_3^{\mathsf T} & 1\end{bmatrix}] that Cholesky-factors the recovered conic stem:[\mathbf{A} \mathbf{A}^{\mathsf T}] out of the affine-stratum
dual quadric (xref:attachment$irurueta-phd-thesis.pdf#page=49[PHD eq. 1.179-1.184]) gives a single
projective&#8594;metric matrix (xref:attachment$irurueta-phd-thesis.pdf#page=51[PHD eq. 1.185-1.186]):

[stem]
++++
\mathbf{T}_{PM} = \mathbf{T}_{AM}\,\mathbf{T}_{PA} = \begin{bmatrix} \mathbf{A}^{-1} & \mathbf{0}_3 \\ \boldsymbol{\pi}_\infty^{\mathsf T} & 1 \end{bmatrix}
++++

Inverting it (xref:attachment$irurueta-phd-thesis.pdf#page=51[PHD eq. 1.189-1.192], via blockwise matrix
inversion) and substituting into the dual-quadric
transform rule shows that in *any* projective frame
(xref:attachment$irurueta-phd-thesis.pdf#page=52[PHD eq. 1.193-1.195]):

[stem]
++++
\mathbf{Q}^{*\prime}_\infty = \begin{bmatrix} \boldsymbol{\omega}^*_\infty & -\boldsymbol{\omega}^*_\infty\,\boldsymbol{\pi}_\infty \\ -\boldsymbol{\pi}_\infty^{\mathsf T}\,\boldsymbol{\omega}^*_\infty & \boldsymbol{\pi}_\infty^{\mathsf T}\,\boldsymbol{\omega}^*_\infty\,\boldsymbol{\pi}_\infty \end{bmatrix}, \qquad \boldsymbol{\omega}^*_\infty = \mathbf{A} \mathbf{A}^{\mathsf T}
++++

i.e. the dual absolute quadric in an arbitrary projective frame packages *both* the dual image of the absolute
conic stem:[\boldsymbol{\omega}^*_\infty] (the "DIAC" that reappears in camera calibration, see
xref:pinhole-camera.adoc[]) *and* the direction stem:[\boldsymbol{\pi}_\infty] of the plane at infinity into a single
stem:[4\times4] symmetric matrix. This is why, in self-calibration literature, recovering
stem:[\mathbf{Q}^*_\infty] is treated as *the* way to upgrade a projective reconstruction straight to metric in one
step, rather than recovering stem:[\boldsymbol{\Pi}_\infty] and stem:[\boldsymbol{\Omega}_\infty] separately.

`irurueta-geometry` does **not** ship such a self-calibration/stratified-upgrade estimator -- there is no
`toAffine()`/`toMetric()` on `ProjectiveTransformation2D`/`3D`, and no class under
`com.irurueta.geometry.estimators` or `com.irurueta.geometry.refiners` computes stem:[\boldsymbol{\Pi}_\infty] or
stem:[\mathbf{Q}^*_\infty] from image data. What the library *does* give you is exactly the algebraic building blocks
above -- the canonical values of stem:[\boldsymbol{\Pi}_\infty], stem:[\boldsymbol{\Omega}_\infty] and stem:[\mathbf{Q}^*_\infty],
and the one-directional Euclidean&#8594;metric&#8594;affine&#8594;projective upgrade chain -- so that, given a
`Plane`/`Conic`/`DualQuadric` identified by some other means (vanishing points, orthogonal-plane constraints,
Kruppa's equations, etc.), an application can still build the matrices stem:[\mathbf{T}_{PA}]/stem:[\mathbf{T}_{PM}]
above by hand.

== From theory to code

The canonical constants above are not just theory -- they are literally the values the library's factory
methods return:

[source,java]
----
// Pi_infinity = (0, 0, 0, 1)^T                          -- PHD eq. 1.118 / HZ Sec. 3.5
Plane planeAtInfinity = Plane.createCanonicalPlaneAtInfinity();

// Omega_infinity = I_3x3                                 -- PHD eq. 1.160 / HZ eq. 3.21
Conic absoluteConic = Conic.createCanonicalAbsoluteConic();

// Omega*_infinity = I_3x3 = (Omega_infinity)^-1           -- PHD eq. 1.162
DualConic dualAbsoluteConic = DualConic.createCanonicalDualAbsoluteConic();

// Q*_infinity = diag(1, 1, 1, 0)                          -- PHD eq. 1.169 / HZ eq. 3.24
DualQuadric dualAbsoluteQuadric = DualQuadric.createCanonicalDualAbsoluteQuadric();
----

And the one-way upgrade chain (Euclidean &#8594; metric &#8594; affine &#8594; projective) walks the strata
exactly in the direction the invariants above allow -- each step *adds* a degree of freedom (scale, then general
linear skew, then the projective row) rather than removing one:

[source,java]
----
Rotation3D rotation = new AxisRotation3D(0.0, 0.0, 1.0, Math.PI / 6.0);
double[] translation = {1.0, 2.0, 3.0};
EuclideanTransformation3D euclidean = new EuclideanTransformation3D(rotation, translation);

// adds a uniform scale (MetricTransformation3D.DEFAULT_SCALE = 1.0 initially)
MetricTransformation3D metric = euclidean.toMetric();

// embeds scale * R as the general 3x3 linear part -- concretely "metric subset of affine"
AffineTransformation3D affine = metric.toAffine();

// appends the implicit last row [0 0 0 1] -- this IS T_A from PHD eq. 1.120 / HZ table 3.2,
// the exact matrix shape whose invariance of Pi_infinity was proved above
ProjectiveTransformation3D projective = affine.toProjective();
----

`AffineTransformation3D.toProjective()` (`AffineTransformation3D.java:1018-1020`) builds
`new ProjectiveTransformation3D(a, translation)`, which is precisely the block form
stem:[\begin{bmatrix} \mathbf{A} & \mathbf{t} \\ \mathbf{0}^{\mathsf T} & 1\end{bmatrix}] used throughout the proofs above --
seeing that constructor call is seeing
xref:attachment$irurueta-phd-thesis.pdf#page=36[PHD eq. 1.120] typed out in Java. Similarly,
`MetricTransformation3D.toAffine()` (`MetricTransformation3D.java:272-274`) builds
`new AffineTransformation3D(scale, getRotation(), getTranslation())`, embedding stem:[\sigma \mathbf{R}] as the
linear part -- the exact matrix that appeared as stem:[\mathbf{A}=\sigma \mathbf{R}] in the necessity proof of
&#167;Invariants above.
